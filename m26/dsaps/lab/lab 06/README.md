# Lab 06

| # | Problem (this folder) | Closest match | Notes |
|---|---|---|---|
| 1 | [valid-brackets](valid-brackets.md) | [LeetCode 20 — Valid Parentheses](https://leetcode.com/problems/valid-parentheses/) | Identical problem, with a larger bound (length up to 10^6 instead of 10^4) and `YES` / `NO` output. Push each opening bracket; on a closing bracket the stack must be non-empty with the matching opener on top, and the stack must be empty at the end, O(n). An odd length can be rejected straight away. |
| 2 | [escape-from-big-vp](escape-from-big-vp.md) | [LeetCode 1020 — Number of Enclaves](https://leetcode.com/problems/number-of-enclaves/) | Same grid and limits (R, C ≤ 500) in a story skin, but the complement: 1020 counts the land cells that cannot reach the edge, while this counts the `S` cells that can, i.e. total `S` minus 1020's answer. Multi-source BFS from every `S` on the border and count the cells reached, O(R·C). [LeetCode 130 — Surrounded Regions](https://leetcode.com/problems/surrounded-regions/) uses the same border flood fill. A recursive DFS can go 250000 calls deep on a snake-shaped gang, so use BFS or an explicit stack. |
| 3 | [endless-trip](endless-trip.md) | [AtCoder ABC 245 F — Endless Walk](https://atcoder.jp/contests/abc245/tasks/abc245_f) | Identical problem, with the same constraints and samples (AtCoder also guarantees no self-loops and no repeated edges; the statement here leaves both out). A city works exactly when some path from it reaches a directed cycle, so this is N minus the safe nodes of [LeetCode 802 — Find Eventual Safe States](https://leetcode.com/problems/find-eventual-safe-states/). Kahn's algorithm on the reversed graph: queue every city with out-degree 0, and on removing one, decrement the out-degree of every city with a road into it; the cities never removed are the answer, O(N + M). Three-colour DFS works too, but a chain of 2·10^5 cities is deep for recursion. |
| 4 | [max-of-min-for-every-window-size](max-of-min-for-every-window-size.md) | [GeeksforGeeks — Max of Min for Every Window Size](https://www.geeksforgeeks.org/problems/maximum-of-minimum-for-every-window-size3453/1) | Identical problem, with the same samples (LeetCode has no plain equivalent). With a monotonic stack, find for each `i` the nearest strictly smaller element on the left and on the right; `arr[i]` is the minimum of a window of length `len = right - left - 1`, so set `ans[len] = max(ans[len], arr[i])`. Then sweep `k` from `n - 1` down to 1 with `ans[k] = max(ans[k], ans[k + 1])`, since a minimum that covers a longer window also covers every shorter one, O(n). The brute force over every window is O(n²), too slow for n = 10^5. |
