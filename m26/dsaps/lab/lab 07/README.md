| 1 | [maximum-sum-of-k-consecutive-numbers](maximum-sum-of-k-consecutive-numbers.md) | [LeetCode 643 — Maximum Average Subarray I](https://leetcode.com/problems/maximum-average-subarray-i/) | Same fixed-size sliding window, but 643 returns the best average (the best sum divided by `k`) with smaller bounds, while this prints the sum itself. Sum the first `K` elements, then slide one step at a time by adding `A[i]` and subtracting `A[i - K]`, keeping the maximum, O(N). A window sum can reach 5·10^14 in magnitude, so use 64-bit, and start the best value from the first window rather than 0, since every sum can be negative (Sample 2). |
| 2 | [districts-of-roadville](districts-of-roadville.md) | [CSES 1683 — Planets and Kingdoms](https://cses.fi/problemset/task/1683) | Same problem in a story skin, with the same limits (N ≤ 10^5, M ≤ 2·10^5): a district is a strongly connected component, and CSES also asks you to label every planet with its kingdom, while here only the count is printed (LeetCode has no plain equivalent). Kosaraju (DFS finish order, then DFS on the reversed graph in reverse finish order, counting the starts) or Tarjan, O(N + M). A chain of 10^5 towns makes a recursive DFS that deep, so an iterative DFS is safer. |
| 3 | [subarrays-with-exactly-k-different-numbers](subarrays-with-exactly-k-different-numbers.md) | [LeetCode 992 — Subarrays with K Different Integers](https://leetcode.com/problems/subarrays-with-k-different-integers/) | Identical problem, with the same first two samples; N goes up to 2·10^5 here instead of 2·10^4. Count with "at most" windows: exactly(K) = atMost(K) − atMost(K − 1), where atMost(K) slides a window, shrinking from the left while it holds more than K distinct values and adding `right − left + 1` at each step, O(N). Since `A[i] <= N`, a plain count array works instead of a hash map. The answer can reach about 2·10^10, so it needs 64-bit. |
| 4 | [high-scores](high-scores.md) | [CSES 1673 — High Score](https://cses.fi/problemset/task/1673) | Identical problem, with the same limits and sample. Bellman–Ford for the longest path (or negate every `x` and find the shortest): relax all edges n − 1 times, then once more, and answer `-1` only if a node that still improves is both reachable from room 1 and able to reach room n. A positive cycle elsewhere does not matter, so mark both sets with a forward search from 1 and a search from n on the reversed graph, O(n·m). Scores reach about 2.5·10^12, so use 64-bit and skip relaxing from rooms not yet reached. |
| 5 | [remove-minimum-routes](remove-minimum-routes.md) | [Codeforces 449B — Jzzhu and Cities](https://codeforces.com/problemset/problem/449/B) | Same problem, with the same first sample; Codeforces allows several train routes to the same city (so ties between trains matter there), while here there is at most one per city. Dijkstra from city 1 over roads and train routes together. A train route to `s` can be closed if `y > dist[s]`, or if `y == dist[s]` and some road `(u, s, x)` already gives `dist[u] + x == dist[s]`; every other train route must stay, O((n + m + k) log n). Distances reach about 10^14, so use 64-bit. |
