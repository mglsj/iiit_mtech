| 1 | [round-robin](round-robin.md) | [LeetCode 2073 — Time Needed to Buy Tickets](https://leetcode.com/problems/time-needed-to-buy-tickets/) | Close analog only: 2073 is round robin with a time slice of 1 and asks for one person's finish time, while this has a slice of `q` and prints every process's end time in process order. Simulate with a queue of indices: pop the front, run it for `min(q, remaining)`, advance the clock, and push it back if it is not done, else record the clock as its end time. There are at most Σ⌈b_i / q⌉ ≤ 10^6 turns, so the plain simulation fits easily; the largest end time is Σb_i ≤ 10^6, which fits in 32 bits. |
| 2 | [pokemon-the-ultimate-pokemon-league-challenge](pokemon-the-ultimate-pokemon-league-challenge.md) | [GeeksforGeeks — Floyd Warshall](https://www.geeksforgeeks.org/problems/implementing-floyd-warshall2042/1) | Same all-pairs shortest path on an adjacency matrix in a story skin (LeetCode has no plain equivalent); the older GfG version uses the same `-1` for "no edge" and has this Sample 2 as its first example. Floyd–Warshall with `k` as the outer loop, O(n^3) for n ≤ 100. The catch is `-1`: skip a relaxation when `d[i][k]` or `d[k][j]` is `-1`, and treat `d[i][j] == -1` as infinity when comparing, or swap `-1` for a large value first and back again on output. Edge costs can be 0, so `0` must not be read as "no edge". |
| 3 | [pair-xor-sum](pair-xor-sum.md) | [GeeksforGeeks — Sum of XOR of All Pairs](https://www.geeksforgeeks.org/problems/sum-of-xor-of-all-pairs0723/1) | Identical problem (LeetCode has no plain equivalent; [LeetCode 477 — Total Hamming Distance](https://leetcode.com/problems/total-hamming-distance/) uses the same per-bit trick). Bit `b` is set in `a_i ⊕ a_j` exactly when one of them has it and the other does not, so if `c` numbers have bit `b` set it adds `c · (n − c) · 2^b`; sum over the 30 bits, O(30·n). The O(n²) loop over pairs is too slow for n = 10^5. The answer can reach about 5·10^18, which still fits in `long long`, but every product must be done in 64-bit. |
| 4 | [optimize-snakes-ladders-game](optimize-snakes-ladders-game.md) | [HackerRank — Snakes and Ladders: The Quickest Way Up](https://www.hackerrank.com/challenges/the-quickest-way-up/problem) | Identical problem, with the same sample; HackerRank wraps it in several test cases, here there is one board. [LeetCode 909 — Snakes and Ladders](https://leetcode.com/problems/snakes-and-ladders/) is the same BFS on a boustrophedon grid. Map every square to where it finally lands (`jump[s] = e` for each ladder and snake), then BFS from square 1 where each roll 1–6 is one edge and a roll past 100 is skipped; the distance to 100 is the answer, or `-1` if it is never reached (for example, six snakes in a row block every roll). Only 100 squares, so O(600). |
| 5 | [xor-walk](xor-walk.md) | [Codeforces 1760G — SlavicG's Favorite Problem](https://codeforces.com/problemset/problem/1760/G) | Identical problem, with different samples. Walking an edge twice cancels it, so `x` at a vertex is just the path XOR from where she started or landed. DFS from `a` without ever stepping onto `b` and store every value `x` it reaches in a set; then DFS from `b` and compute the XOR from `b` to every other vertex `v`. The answer is `YES` if some vertex `v ≠ b` has its XOR from `b` in the set (teleport to `v` holding that value, or `v = a` when no teleport is needed), O(n log n) per test. Use an iterative DFS, since a path-shaped tree is 10^5 deep. |
